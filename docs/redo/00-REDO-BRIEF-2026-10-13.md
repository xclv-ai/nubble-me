# Redo — brief (2026-10-13, 22:10)

## The owner's instruction
"Redo app, not rush: create concept and read best practices, plan UX, then UI, and test." · "Don't rush with Swift — nothing valuable or useful." · "Your approach just wasted time."

## What the owner wants (his words, 2026-10-13)
- Target: neurodivergent AI-startup founders — "we don't have patience · infographic instead of long text · red alert when competitors posted something important · clear signals WHAT TO DO."
- Character: Dr HAOS as the main hero, "a bit arrogant", with POKPOK's personality (House M.D. for brands, receipts, dark humour).
- Feel: "engaging, like a game a bit · memorable · magical for strange AI founders · quirky but ultra quality · very modern but not boring."
- Visual: "realistic low-poly 3D style with realistic textures and lighting" · "3D nicely animated Dr HAOS avatar, live animated" · "gyroscope should influence 3D objects — tilt changes the angle and the visible shadow."
- Colour: "keep colours from POKPOK" but "Dr HAOS colours, not full POKPOK identity" (teal #0A3B44, pink #FFC4D6, yellow #F5F900, beige #E8E0D1, off-white #FDFDFC, red for competitors).
- Type: "contrast of size of headlines and other text as in your first prototype" (big headline, small text).
- Typeface: Geist (Vercel) asked for the first prototype; Instrument Serif/JetBrains Mono are POKPOK's — decide in the concept.
- Kept features: 3 signals a day then discharge; each signal = headline + Dr HAOS verdict + ℞ (prescription); depth levels 00 Signal · 01 Condensed · 02 Article · 03 Expanded · 04 For you; competitor watchlist → code red; prescriptions list + Lock Screen widget; frontier lines from gpt-5.4-nano via Vercel AI Gateway; on-device levels.

## What went wrong (so the redo doesn't repeat it)
1. Code before design: SwiftUI written in one-shot passes, judged from a screenshot, patched — twelve build/install cycles on a layout that was never designed.
2. No concept: no single idea or metaphor; screens were a style applied to a list.
3. Navigation: the rounds opened as a full-screen cover without an exit; the owner could not reach the menu.
4. Density and type: 7 type sizes per screen, cramped yellow blocks, text unreadable; the first prototype's big/small contrast was lost.
5. Wrong tool for "like a game": a form layout where a lit, living character was asked for; the 3D stage was extruded SVG, not a modelled character.
6. Reporting before verifying: "excellent direction" was declared on a mockup; the phone showed otherwise.

## The order now
1. Best practices (docs/redo/01) and the 3D stack (docs/redo/02) — read, distilled, cited.
2. Concept — one idea; 3 variants; the owner picks.
3. UX plan — flows, screens, states, gestures, exits; reviewed against the rules; the owner approves.
4. UI — a playable prototype in the phone's browser (Three.js/WebGL: character, lighting, gyroscope, plates, type); the owner tests live; iterate until he says it is right.
5. Only then native build, tested against the prototype; TestFlight on his word.
