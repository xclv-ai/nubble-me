# Worked example: one update, different decisions

**Status:** hand-authored fictional fixture illustrating the proposed method. It is not generated system output, a real competitor announcement, or study evidence. All organizations and capabilities below are hypothetical except the use of POKPOK as the reader's illustrative project name. No current product facts about POKPOK are asserted.

## Reader A: a POKPOK positioning decision

**Illustrative context version:** `pokpok-positioning-demo-v1`  
**Focus:** explaining a hypothetical product that compares how people and AI engines perceive a brand.  
**Goal:** make that distinction clear to prospective buyers.  
**Pending decision:** whether to revise the comparison page this week.  
**Current plan:** keep the product roadmap unchanged and review positioning weekly.  
**Constraints:** founder can spend 30 minutes verifying a competitor; no engineering work this week.  
**Attention budget:** two minutes for the brief, including evidence inspection.  
**Horizon:** the next positioning review.

### Short / relevant to this focus

Northstar is piloting weekly AI brand mention monitoring with visible sample questions and answer evidence ([S1](#s1), [S2](#s2)). This overlaps with the AI-monitoring part of the illustrative positioning. The announcement does not establish whether Northstar compares human brand perception with AI answers ([S3](#s3)); that distinction needs verification before describing a competitive gap.

### So what?

**Possible change — inference:** buyers could group the two offerings together if both are described only as AI brand monitoring. This is a positioning risk hypothesis; the source contains no buyer research.

**Mechanism:** the announced monitoring capability overlaps with part of the reader's product description ([S1](#s1)), while the proposed human-versus-AI comparison remains unverified for the competitor ([S3](#s3)). Shared language could obscure a meaningful difference if that difference exists.

**Proposed next step — verify:** spend up to 30 minutes checking the pilot description or demo for human-versus-AI comparison. If that difference is confirmed, revise one comparison-page sentence to explain it accurately. Keep the roadmap unchanged on this evidence.

**Assumptions:** the illustrative POKPOK comparison is delivered as described; prospective buyers care about the distinction; comparison-page copy is within the founder's control. These are context assumptions, not facts from Northstar's announcement.

**Unknowns:** actual competitor feature coverage, standalone price, broad availability, and buyer response. “Not discussed” does not mean “not supported.”

**What would change this proposal:** evidence of comparable human-versus-AI analysis would require reconsidering the proposed differentiation. Evidence that buyers already understand the distinction would reduce the need for a copy change.

### So what?

**Outcome: no action warranted for the stated decision.** The update supplies no evidence that should change this sprint's accessibility fixes. Continue the current regression list. Reconsider only if a later source identifies a relevant testing capability or requirement.

This conclusion concerns this reader's scope. It is not a judgment that the announcement is unimportant to everyone.

## What this example demonstrates

| Property | Observable behavior |
|---|---|
| Facts stay stable | Both readers receive the same underlying announcement. |
| Relevance changes | Reader A has a positioning question; Reader B has an unrelated engineering decision. |
| Source and inference stay distinct | Potential buyer confusion is explicitly a hypothesis, not a reported event. |
| Missing evidence stays missing | Neither output asserts that the competitor lacks an unmentioned feature. |
| Action is bounded | Reader A gets a verification task within the stated resources; Reader B gets no new task. |
| Depth is recoverable | Every factual premise links to the full fixture. |

## Important limit

A well-written hand-authored example can clarify the method. It cannot establish that a model reliably follows it, that two minutes is sufficient, or that the outputs improve real decisions. Those are questions for the [evaluation protocol](../PAPER_PROPOSAL.md#evaluation-protocol).
